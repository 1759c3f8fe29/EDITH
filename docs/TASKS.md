## Ground rules

- **No stubs.** A task is done only when its behavior is real and has been run. Spec §3, §77–81, §114.
- **No fake success.** If a capability cannot work in this environment, detect it and say so. Never simulate. §78, §110.
- **Verify, don't assume.** A tool returning without error is not proof the action happened. §30.
- **Self-contained.** NEXUS uses its own credentials, entered through its own settings into the OS keyring. No data, keys, or code pulled from other projects on this machine. §13, §65.
- **Vertical slices.** Each phase ships something end to end: input → permission → execute → verify → persist → log → UI.
- **Local-first storage.** SQLite is the source of truth; Firestore is an additive sync/backup layer (Phase K). All data access goes through the Python core so the UI cannot bypass the permission engine. §65.
- **No local model.** Routing is cloud-only by decision; the spec's local-AI sections (§100, §101) are handled by honest unavailability messaging, not simulation. §78.
- **One model per job.** `deepseek-v4-flash-0731` is the main AI — ordinary conversation goes to it first. Reasoning and coding/expert head their own specialists (Nemotron 3 Ultra / DeepSeek V4 Pro), vision, OCR, video, embeddings and rerank each go to a dedicated NVIDIA NIM specialist, and speech (STT/TTS) goes to Mistral Voxtral — separate models with separate call contracts, because pretending otherwise produces unexplainable errors. Phase M. §10, §12.
- **Status here is evidence, not intent.** A `✔` means the behaviour was executed on this machine and the output inspected — not that the code looks finished. Where a task is part-done, `◐` names the missing part rather than rounding up. Marking from a code read would make this document exactly the kind of confident fiction §3 forbids.
- **Bulk file work is previewable and reversible.** Anything that touches many files at once (Phase N) resolves to an explicit list, shows it before acting, and records an undo journal. "Organize my downloads" that cannot be undone is a worse offer than doing it by hand. §25, §62, §98.
- **Watching is opt-in.** Every continuous monitor ships off. NEXUS can see the screen, follow window focus, and track the system — after the user turns each one on, and while an indicator says so. Phase L. §15, §66.

- **C10 ✔** Consent for an action nobody is watching: an automation carries the capabilities it was armed for, and the fire path checks that record **and** the live engine. §34, §36, §5. *Built 2026-09-03, because the engine (I8) had made it possible for NEXUS to act with no one in the room, and the permission spine assumed there was. Migration v4 adds `automations.capability_scope` (a JSON array, `DEFAULT '[]'`) and `automation_runs.denied_capability` -- a column rather than a key inside the run's `detail` JSON, because "which rules are being refused, and for what" is a question worth being able to ask in SQL. The default is what makes the migration safe on your populated database: the only action kind that exists is `notify`, which writes an `activity` row and publishes on the in-process bus and reaches nothing else, so the `frozenset()` on its registry entry is a claim rather than an omission and every row that exists today is already correctly scoped by an empty list. Nothing is disarmed by upgrading. **The capabilities are declared on the registry entry**, so adding an action kind *is* declaring its powers; a parallel lookup table can be forgotten by whoever adds the next kind, and the failure mode of forgetting is an action that runs unattended having declared it needs nothing. **The gate has two layers and neither one is redundant.** The stored scope alone would mean that revoking a permission on the Permissions screen does nothing to rules armed before the revocation. The live engine alone would let trusted mode silently widen a rule the moment someone edits its action, because trusted mode says yes to every question it was ever going to ask -- and that version passes every other test in the file, which is why `test_trusted_mode_does_not_widen_a_stored_scope` is named in the file's own docstring as the one that matters. The gate calls `evaluate`, not `require`, and reads `ask` as a refusal: nobody is watching when a rule fires at 20:30, so `require` would park the tick loop for the full 180s request timeout and then fail closed anyway, and "NEXUS would have asked you" is not consent. Permanence comes from `Decision.source`: only `hard_limit` is refused above every grant and every setting, so only that clears `next_run_at`; a `deny` or an `ask` is something you can change, so the rule keeps its schedule. Verified by 24 tests in `tests/test_automation_capability_scope.py` (suite total 456), mutation-checked at 24 mutants across three files: 24 killed, 0 survived, 0 refused. The three that carry the design are *stored-scope check deleted*, *engine check deleted* and *ask read as allowed*. Two survivors in the first campaign each produced a change to the code rather than a softened test. One exposed an `except UnknownActionKind` branch in the gate that could not be reached at all, since `execute` returns first on an unknown kind -- the gate now takes the resolved `ActionKind` so the branch cannot exist, because dead defensive code is worse than none: it reads as a handled case. The other exposed a missing test for the PATCH path falling back to the stored scope, without which every edit to an action would have demanded fresh consent for powers it already had. One real latent bug surfaced the same way: `ACTION_KINDS` was an import-time `tuple(_ACTIONS)`, so the routes validated incoming actions against a snapshot while `execute` dispatched from the live dict -- replaced with `action_kinds()`, read from the registry each call. The route reaches the same judgement while the user is still looking at the form, refusing the three ways a scope can disagree with reality: a capability no catalogue entry answers to, a scope **narrower** than the action needs, and a scope **wider**. It **never infers the scope from the action** -- auto-filling it would turn a record of consent into a rubber stamp and make the check unfailable. Surplus is refused rather than trimmed: nothing unsafe follows from it, but a rule recorded as authorised for something it cannot do is a false statement about the system, and trimming would hide a disagreement between the client and the core. Not built, on purpose: **no consent UI.** Every rule's scope is `[]` today because `notify` declares nothing, so a picker or a scope display would render nothing -- dead UI, which the ground rules forbid. `capability_scope` and `denied_capability` are typed in `lib/api.ts` so that the next change does not start from a lie, and nothing more. **The live database at `~/.local/share/nexus/nexus.db` is still at v3**: the core is stopped by your instruction, so v4 has run only against the suite's fresh database and a temp file. The migration test compensates for the one condition a fresh database never has, applying v1-v3 to a raw sqlite file, inserting a notify automation and a run, then applying v4 and asserting the scope reads `[]`, the rule is still enabled, `next_run_at` is undisturbed and the action is byte-identical.*

## Phase K — Cloud Sync: Firestore (K1–K6)

Additive. NEXUS is fully usable before any of this exists — that is the point of local-first.

- **K1 ⚑** Create the Firebase project, enable Firestore and Firebase Auth, install the emulator suite. Credentials to the OS keyring (A8), never the repo.
- **K2** Sync engine foundation: an outbox table fed by B2's `rev` counters and B8's tombstones, plus a per-collection sync cursor. Sync is a background service, never in a request path.
- **K3** Push: batched, idempotent upload of local changes with exponential backoff, and write throttling for high-frequency data (activity, system metrics) so metered usage cannot run away.
- **K4** Pull: fetch remote changes since the cursor and apply them to SQLite inside a transaction, preserving local invariants.
- **K5** Conflict resolution: a deterministic, documented policy (per-field `updated_at` with a stable tiebreak), surfaced to the user when a conflict is not trivially resolvable. §62.
- **K6** Selective sync + Firebase Auth with uid-scoped security rules, emulator-tested. Only user-approved categories leave the device — never every local artifact — with sync status, pause, and disable in Settings. **No service-account key ships in the desktop binary.** §72, §65, §71.

## Phase L — Presence: seeing, controlling, monitoring (L1–L16)

Phase D gives NEXUS hands. This phase gives it *presence* — the difference between a tool you invoke and an assistant that is already aware. Everything in D is one-shot: ask, act, answer, forget. Everything here runs between requests.

Two rules govern the whole phase, and they are not negotiable:

1. **Every watcher is off until switched on.** NEXUS never arrives watching. §15, §66, §99.
2. **Observation is not authorization.** Seeing that a build failed does not permit fixing it. Every proactive path ends at a *proposal*. §31.

### Bulk file work

Each of these resolves to an explicit list, shows it, then acts — and every one of them writes to the same undo journal (N5). A bulk operation that cannot be undone is a worse offer than doing it by hand on a Saturday.

- **N1** Duplicate finder: group by size, then by a cheap head-and-tail hash, then by full content hash only for the survivors — so a folder of large videos is not read end to end to prove they differ. Reports groups and reclaimable bytes, **never auto-deletes**, and marks which copy looks canonical (oldest, or the one outside Downloads) while leaving the choice to the user. §23, §98.
- **N2** Rename by pattern: a stated transform (numbering, date prefix from EXIF or mtime, case, find-and-replace, extension normalisation) previewed as old → new for every file, with collision detection **before** anything moves and a refusal to proceed on any collision it cannot resolve without loss. §23, §62.
- **N3** Bulk organize: classify by extension, MIME sniff, mtime and name pattern into a proposed destination tree, shown as a full move list the user edits or approves. The classifier's rules are visible and editable — an assistant that silently invents a folder taxonomy is not organizing, it is hiding things. §23, §98.
- **N4** Archive: compress a folder or a chosen set to `.tar.gz` or `.zip`, verify the archive by listing it back and comparing the manifest against the source, and only then offer to remove the originals as a separate confirmed step. §23, §30.
- **N5** Undo journal for bulk operations: every move, rename and delete recorded with both paths and a batch id, so "undo that" reverses the whole batch in reverse order, reporting precisely which items could not be reversed and why (destination changed, source gone, trash emptied). Bounded by retention like everything else. §62, §64, §70.

### Browser control

- **N6** Real browser control via the DevTools protocol: launch or attach to a Chromium-family browser with a debug port, then list tabs, open, close, navigate, read the current URL and title, and extract page text. Verified by reading back the resulting URL, never by a zero exit code. Where no debug port is reachable it says exactly that and falls back to D7's open-a-URL, which is all the OS alone can promise. §23, §30, §78.
- **N7** Browser session boundary: attaching to the user's everyday profile means inheriting every logged-in session in it, so profile choice is an explicit, remembered decision — a separate NEXUS profile by default, the personal profile only on a specific grant that states what it exposes. Adds `browser.control` to C1's catalogue as its own high-risk capability, because reading page content from a logged-in session is categorically not "open a web page". §5, §24, §99.

### Messaging

- **N8** WhatsApp messaging through WhatsApp Web (N6) plus input synthesis (L11): resolve the contact, compose, **show the exact recipient and message text for confirmation**, send, then verify the message appears as sent in the thread. No unofficial API and no message queue that pretends to have delivered something — if the tab is not logged in, or the contact is ambiguous, it says so and stops. A message sent to the wrong person cannot be recalled, so ambiguity is always an ask. Adds `message.send`. §30, §98.

### Language and system

- **N9** Compound and vague command resolution: "close all Chrome windows" enumerates the real windows and confirms the count before acting; "switch to Spotify" resolves against what is actually running and offers to launch it if it is not; "clean up my downloads" is refused as a mission until N3 has produced a concrete list. Every plural verb becomes an explicit enumerated set the user sees — the plan names the four windows it is about to close. §22, §28, §98.
- **N10** System guardian, defined rather than gestured at: identify the top resource consumers with real numbers from `/proc`, and offer a small set of genuinely safe actions — terminate a named process on confirmation, clear a specific application cache, list large or old files for the user to decide about. It never "optimizes" by doing something it cannot describe, and it never touches system directories. Anything requiring root is stated as such, not attempted. §35, §69, §98.

### The two remaining promises

- **N11** The 2070 interface language, on top of I1's mechanics: dark by default with a single accent, real depth from layered translucency rather than drop shadows, motion that carries state and never decorates, monospace for anything the machine measured, and every animation tied to something actually happening. The hard rule is §67 and §92 — the futurist look must survive reduced-motion, high-contrast and screen-reader use with nothing lost, and no state may exist only as an animation. A glowing orb that is the *only* indication NEXUS is listening is a bug, however good it looks. §51–54, §94.
- **N12** Emotional voice intelligence, scoped honestly: the TTS specialist (M8) is driven with prosody, rate and voice chosen to match message *kind* — an error spoken plainly and slowly, a confirmation briefly, a long answer with pauses at real boundaries. This is expressive delivery, not emotion recognition: NEXUS does not claim to detect the user's mood from their voice, because it cannot, and it must not perform sympathy it has no basis for. If the chosen voice supports no prosody control, it says so instead of silently ignoring the request. §6, §10, §78.

- **P1 ✔** Outcome store: schema v5 `model_outcomes`, one row per real provider
  call, with the reward computed *at the moment of the call* and stored rather than
  recomputed — a changed formula must not silently rewrite history the learner then
  trains on. `verified` stays three-valued so "could not be checked" never scores
  as "checked and wrong". Failures split durable (0.0) from transient
  (`TRANSIENT_REWARD`, nonzero) so a model that timed out once stays explorable
  rather than being benched on one bad afternoon. §30, §38. *`nexus/db/repos/model_outcomes.py`.*
- **P2 ✔** Reinforcement learning: a contextual bandit over each job's chain —
  Thompson sampling from a Beta posterior per model, reward acting as fractional
  success. Three constraints make it safe: it receives only candidates that already
  cleared `_why_not`, so it **can reorder but never admit** a model the checks
  rejected; chain position is the prior, so a fresh install reproduces the declared
  order exactly instead of shuffling hand-ordered engineering judgement; and every
  reorder returns the counts that caused it, which the `Decision`'s reason carries,
  so preferring the second model is never the silent substitution `jobs.py`
  forbids. Sampling rather than ranking is deliberate — always taking the current
  best means never finding out a model has been fixed. §15, §30, §38.
  *`nexus/learning/bandit.py` + `outcomes.py`, wired in `Router.resolve`/`stream`,
  switch `router_learning_enabled` (default on: it observes NEXUS's own calls, not
  the user). 14 tests, 6/6 mutations killed.*
- **P5 ✔** Anticipation (§37, §52; closes O7): `nexus/core/trends.py` — an ordinary
  least-squares fit over a bounded in-memory window, plus the four refusals that are
  the actual feature, because a projection is a claim about the future and the cheap
  version of this is a liar the user cannot check. It **refuses to speak from too few
  points** (two always fit perfectly, which is why they prove nothing), **refuses when
  the fit is bad** (CPU bouncing 10–90 has a slope that means nothing — R² below
  `MIN_R2` is reported as *no trend*, not a weak one), **refuses to project further
  ahead than it has watched** (`MAX_PROJECTION_RATIO`; four minutes of data may not
  speak about the next hour), and **refuses to call a flat series a slow climb**
  (without `FLAT_SLOPE`, float noise on a steady value projects thousands of minutes
  out). Every trend carries its window, sample count and R² so a user who doubts it
  can argue instead of merely believing. Wired into `SystemMonitor`: CPU and memory
  climbs are announced *before* they cross their threshold and not after (that is the
  alert's job), once per ten minutes rather than every tick, and a discharging battery
  projects to a time — the §52 sentence that was previously not constructible. A plug
  event clears the discharge window rather than fitting a line across it, and a
  restart drops the window rather than asserting continuity over a gap. Scored
  **quieter than the alert it predicts** (`system.trend` urgency below
  `system.memory`, actionability above it, confidence 0.75 because the detector is a
  line fit) — inverting that would train the user to distrust the louder of the two.
  §31, §35, §37, §52. *19 tests, 7/7 mutations killed, each confirmed to have applied.*
- **P6 ✔** Live screen reading — *"it can see it live"*: `nexus/tools/screen.look`,

  the missing half of "see your screen". It captures, hands the frame to the vision chain,

  a backend that wrote a non-image is discarded rather than described; a frame over the

  *12 tests, 4/4 mutations killed — including one mutation that survived until the vision

- **P7 ✔** Streaming speech-to-text — *"stt,tts must be streaming"*, the half that was
  not: TTS has been segmented since H10, but hearing called `offline_recognize` on the

  **Measured live against the real endpoint** — one sentence came back as `'Next'` →

  a TTS→STT round trip through the router's own choice returned the spoken sentence
  verbatim. Two properties are load-bearing and both are pinned by test: partials are
  **revisions, not appends** (`is_final` is a field the recogniser reports rather than
  something a caller infers, and joining partials would read as the machine changing its
  mind), and a failure on the worker thread **crosses back through the queue** to the
  consumer — without that, a caller waits forever on a stream that already died, which is

- **P8 ✔** Clipboard write, which was silently broken: found by driving the control tools

  keeps holding the selection** — that is how a clipboard outlives the program that set it

  EOF that never came. Measured: a **5-second stall on a write that takes 8 ms**, after
  which the loop swallowed the timeout and told the user *"none of wl-copy, xclip or xsel
  is installed"* about a program that was installed **and had already copied the text**.
  Fixed by passing no capture pipes (verified: 8 ms, and the text sticks), reading the
  clipboard back to verify like every other write tool, and separating "no writer
  installed" from "a writer is installed but the write did not take" — the old message
  named the wrong fix and hid a real defect behind a confident sentence. §48, §60, §78.

  bug. Found only because the test was real-world: no happy-path unit test would have hit
  it, since the write genuinely succeeds.*
- **P9 ✔** Procedural memory — *learning how you work* (closes **O8**): the gap three
  audits named in the same words ("no learned-workflow memory type", so outcome data
  accumulated and nothing improved from it). `nexus/ai/procedures.py` detects recurring
  step sequences across *completed* tasks and proposes them; `procedural` is now a real
  memory category. **It proposes, it never stores** — a learned procedure is a claim
  about how the user works, and a machine that quietly treats its own inference as the
  standard is the §32 violation in a useful costume, so it goes through the same
  approval door as every other memory. Three constraints carry the honesty, each
  mutation-tested: **it requires the pattern twice** (one successful run is a run, not a

## Deliberately honest gaps

Reported as unavailable rather than faked, per §78 and §100:

- **Offline AI: none.** Routing is cloud-only, so without network there is no model to answer. Everything *else* keeps working — conversations, memories, search, settings, system monitoring, file operations, app control — because the store is local. The UI must state which of the two it is. §60, §61.
- **Wake word** until an engine is chosen and confirmed to run on 4 cores (H5).
- **Browser state inspection** beyond opening URLs; real introspection needs an extension or a debug port (D8).
- **Multi-device / IoT** (§33, §34) is architected for and surfaced, but nothing exists to pair with yet — the Devices screen must show that truthfully.
- **Video is frame reasoning, not live vision** (M9). Frames are sampled from a recording and sent; the model describes those frames. NEXUS must never imply it is watching continuously when it is looking at eight stills.
- **Password fields are indistinguishable** to input synthesis (L11). NEXUS cannot tell a password box from any other text box, so it names the target window and asks rather than typing blind.
- **Wayland blocks the X11 tool set.** Capture, window control and input synthesis all go through X11 utilities; under a Wayland session they cannot see the screen at all, and the failure says so rather than returning an empty image.
- **Desktop notification reading** (L7) needs a session bus NEXUS can subscribe to. Where it cannot, the watcher reports unavailable instead of an empty stream that looks like silence.
- **Terminal path checking is literal, and obfuscation defeats it.** C5 refuses a command that *names* a protected path, which closes the door the file tools already guard — `cat ~/.ssh/id_rsa` no longer works just because it went through a shell. It does not survive a variable, an encoding, or a symlink created in the same command. It is built for the case that actually occurs (a model writing a plainly-spelled path, by mistake or because something in its context told it to), and the code says so rather than implying more. The real guarantee is that terminal access ships off and every command is a critical prompt showing the exact text that will run.
- **One screen the spec asks for does not exist:** Devices (I7). The nav rail lists thirteen screens and every one of them is real; there is no fourteenth entry pointing at nothing. `/api/devices` therefore has no surface, and the gap is stated here rather than shown as a disabled button. This line said **two** until 2026-09-03 and named Automations as the other; that screen was built on 2026-09-02 (I8) and the stale claim survived in two places at once -- here, and in the app's own `PENDING_SCREENS`, where Settings was drawing it for the user to read (I8c).
- **Twelve settings are stored and inert**, in seven groups, each with the reason it is waiting named in the Settings screen: `theme` / `reduce_motion` / `font_scale` (this build renders one dark theme, honours no motion preference of its own, and does not scale type), `sync_enabled` / `sync_interval_seconds` (nothing pushes to Firestore yet — SQLite is the source of truth), `session_grants_expire_minutes` (session grants last until the core restarts; no clock times them out), `proactive_suggestions_enabled` / `proactive_quiet_hours` (nothing generates a suggestion, so quiet hours would silence silence), `memory_auto_propose` / `memory_require_approval` (duplicates: the code reads `memory_extract_enabled`, and approval is always required), `diagnostics_verbose`, and `accent` (the accent *is* real, but the shell reads this browser's local storage; the database copy is a leftover). They are grouped under a tab named "Stored but inert", which is the §78 handling — but they are still gaps, not features. Not a defect — A8 reports which source it used, which is the specified behaviour — and a `.env`-sourced key is a key the Settings screen should offer to migrate (E2).
